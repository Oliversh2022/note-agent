# note-agent

把本地 Markdown 笔记库变成「可检索问答 + 自动周报」的命令行 Agent。

## 快速开始

前置条件：Node.js 20+，以及 DeepSeek API key。

1. 安装依赖：npm install
2. 在项目根目录创建 `.env`，写入 `DEEPSEEK_API_KEY=你的key`
3. 启动：npm run dev
4. 输入问题并回车
5. 查看回答后，输入 y 生成并保存周报；输入 n 只保留回答

注意：`.env` 不要提交到 Git，也不要把 key 写进源码或日志。

## 它能做什么

两条路径，一条只读，一条会落盘。


**问答模式**：问什么答什么，只读笔记，不写任何文件。

**周报模式**：回答完之后问一次要不要留档，同意才生成结构化周报并写入文件。

## 目录结构

```
src/
  index.ts              主循环、工具分派、两种模式的分叉
  llm/
    client.ts           API 客户端，key 只从 .env 读
    structured.ts       zod schema、剥 JSON 围栏、重试、渲染 Markdown
  tools/
    searchNotes.ts      按关键词搜 notes/，返回文件名 + 片段
    readNote.ts         读一篇笔记全文（限 notes/*.md）
    writeReport.ts      写文件（路径白名单 + 人工确认）
    confirm.ts          终端 y/n 确认
    logs.ts             每次工具调用追加一行 JSONL
    logCost.ts          token 累计
notes/                  笔记库
reports/                生成的报告
logs/agent.jsonl        运行日志
```


## 四个工具

| 工具 | 谁调用 | 干什么 |
|---|---|---|
| `search_notes(query)` | 模型 | 按关键词搜 `notes/`，返回文件名 + 前后各 20 字片段 |
| `read_note(path)` | 模型 | 读一篇笔记全文，限 `notes/*.md` |
| `write_report(path, content)` | 代码（落盘阶段）；模型原则上也可调 | 写文件，过「路径白名单 + y/n 确认」两道闸 |
| `log_cost(tokens)` | 代码 | 累计 token 用量。**不是模型工具** —— 真实 token 在 `resp.usage` 里，模型看不到 |

前三个注册在 `tools` 数组里，由模型在循环中自主决定调用；`log_cost` 是内部函数，主循环每轮请求后自动调用。原因见下面「设计要点」第 1 条。

## 成本

一次完整运行（问答 + 生成周报 + 落盘）= **5 轮请求、约 7800 tokens**（实测 7815）。其中 4 轮是检索循环，1 轮是结构化周报。

成本由 `log_cost` 累计，结束时打印在最后一行；结构化输出失败重试的每次请求也计入。

## 设计要点

**1. log_cost 不是模型工具，是内部函数。**
它的入参是 tokens，但真实 token 数在 `resp.usage` 里，模型看不到这个字段。如果把它注册成工具，模型只能编一个数字传进来，日志里的成本数据就全是假的。所以由主循环每轮请求完自动累加。

**2. 写文件只有一个出口。**
早期版本有两个出口：循环里模型自己写一次，循环结束后代码又写一次，后者覆盖前者。结果是用户被问两次 y/n、日志里两条 `write_report`、磁盘上只有一份文件。现在系统提示明确「不要自己写文件」，落盘只在最后一步发生。

**3. 确认只发生一次，且发生在内容生成之后。**
先给答案，再问要不要留档。模式不用交互里问、不用问两遍。另外「路径白名单」和「人工确认」是两件事：白名单永远生效、不可跳过；确认可以由调用方在外层做一次，然后给 `writeReport` 传 `confirmed: true`。

**4. 8 轮上限 + 搜索软刹车。**
硬上限 8 轮，转满就中止并打印原因，防止模型无限调工具烧钱。搜索另有软刹车：超过 3 次不是直接中断，而是把「到上限了」作为工具结果告诉模型，让它自己转向整理，用结果引导而不是硬拔电源。

**5. zod 只验形状，不验真假。**
字段齐、类型对、非空，就算通过 —— 内容全是编的也照样通过。实测过：不给素材时模型编出一份通用周报，zod 全部通过。所以结构化校验之后还有人工确认，人确认是最后一道闸。

## 日志格式

`logs/agent.jsonl`，一次工具调用一行，字段：

| 字段 | 含义 |
|---|---|
| `time` | ISO 时间戳 |
| `tool` | 工具名 |
| `args` | 模型给的入参 |
| `result` | 工具返回（成功或失败原因） |
| `ms` | 耗时，**墙钟时间，含人工确认等待** |
| `tokens` | 该轮请求的 token 数；纯本地动作记 0 |
| `retried` | 是否重试过 |

完整样例见 [`samples/agent.sample.jsonl`](samples/agent.sample.jsonl)。

## 已知限制

- 周报素材取自模型的最终回答，不是笔记原文。模型若只回一句「已完成」，结构化那步会拿到贫瘠素材并有编造风险。
- `logs/agent.jsonl` 只追加不轮转，跑多了会变大。
- 一次运行只处理一个问题，退出后重跑。
- 文件访问限定在 `notes/` 和 `reports/`，不支持任意路径。
- 检索是整串子串匹配，不做分词和同义词，关键词选不准就搜不到（实测「计划 复习 资料」这类组合词 0 命中）。
- Windows PowerShell 下输入 `y` 偶尔回显成 `yy`，是终端回显问题，不影响判定。
- 路径白名单用 `path.resolve` 归一化后比对，能挡住 `reports/../evil.md` 这类越界；挡不住符号链接，未做逐级 `lstat` 校验。

每个失败的现象、根因、修法和剩余风险，见 [失败处理说明.md](失败处理说明.md)。
